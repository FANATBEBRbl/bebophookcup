# Архивирование и повторный запуск Bebop Cup

Это сохранённая версия, не исправление причины 0xc0000005. Спавны намеренно не сохраняются.

## До удаления VPS — обязательно

1. Остановить сервер/старый updater через Ctrl+C, чтобы файлы не менялись во время копирования.
2. В актуальном клоне выполнить `git pull origin dev`. Новые скрипты сами на VPS не появляются.
3. В PowerShell под тем же пользователем, который запускал сервер:

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy\Backup-Server.ps1 -IncludeGame
```

По умолчанию CLI ищется в `C:\BebopServer\modlock.exe`. При другом пути добавить `-Base`. `-IncludeGame` сохраняет всю папку Deadlock: потребуется много места, зато останется совместимая версия. Без него игру придётся заново скачать; будущая версия может быть несовместима с Modlock 0.1.73.

4. Скачать **всю** созданную папку `C:\BebopBackup-ДАТА` на свой ПК/диск. Проверить наличие `manifest.json`, `bebop.bundle`, `modlock.exe`, `node.exe`, `host-v0.1.73/modlock-host.exe`. Отсутствующие компоненты host нельзя игнорировать: без них офлайн-запуск невозможен.
5. Только после этого удалять VPS. Git не заменяет эту копию: в нём нет исполняемых файлов сервера и игры.

## Восстановление на новом Windows-сервере

Установить Git for Windows и необходимые игре системные библиотеки/Steam. Скопировать резервную папку. Взять этот скрипт из Git (или клонировать bundle через `git clone X:\backup\bebop.bundle X:\temp-repo`):

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy\Restore-Server.ps1 -Backup D:\BebopBackup -Base C:\BebopServer -Game D:\Deadlock
```

Скрипт проверит SHA256, восстановит Git и программы, создаст `C:\BebopServer\Start-Restored.cmd`. Папка Base должна быть новой. Если игра включена в копию, перенести содержимое backup/Deadlock в D:/Deadlock. Запустить Start-Restored.cmd. Он фиксирует сохранённый commit через BEBOP_REF, не подхватывает новые изменения dev и использует сохранённый MODLOCK_HOST. Удаление BEBOP_REF возвращает автоматическое обновление origin/dev.

Проверить настройки Firewall и панели VPS: игровой порт 27067 (UDP/TCP по конфигурации Modlock), HUD TCP 4321. Не открывать лишние порты. В клиентском guest-hud/guest.cjs сейчас указан старый IP 138.16.184.175: при смене адреса заменить все его вхождения и пересобрать/раздать клиентский комплект. Проверить вход двумя клиентами, HUD, готовность, раунд, выход в наблюдатели и повторное подключение.

## Сбор данных о краше

Обновлённый deploy/server.cjs автоматически пишет UTC-время, commit, PID, события Modlock (кроме частых UI-пакетов), stderr и завершение процесса в Base/logs. Старый уже запущенный updater нужно перезапустить. До этого момента новых логов не будет. Один запуск ограничен восемью сегментами по 16 MiB; папки предыдущих запусков остаются, периодически архивируйте их. Последний сегмент определяется по времени записей, а не номеру файла.

Для полного дампа скачать ProcDump **с Microsoft**, распаковать и запустить отдельный PowerShell (при отказе в доступе — от администратора):

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy\Watch-Crashes.ps1 -ProcDump C:\Tools\procdump64.exe
```

Лицензия принимается пользователем при первом запуске. Наблюдаем `modlock-host.exe`, сохраняем полный дамп при необработанном исключении; максимум пять дампов, затем watcher останавливается. Дампы могут занимать гигабайты. ProcDump влияет на поведение процесса и не гарантирует перехват всех вариантов завершения, особенно при собственном crash handler. Одновременно не подключать другой отладчик.

После сбоя:

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy\Collect-Diagnostics.ps1
```

Будут собраны логи, дампы, события Application 1000/1001 за 7 дней, процессы и версия Windows. Старые события Windows иногда позволяют найти следы даже без console.log. Не публиковать дампы/диагностику в Git: возможны приватные данные памяти. По одному 0xc0000005 виновник не устанавливается.

Документация: https://learn.microsoft.com/en-us/sysinternals/downloads/procdump

## Что хранится в Git

Скрипты игры/HUD, тесты, готовая VPK, исходная small.vmap и custom signs в map-source, скрипты упаковки/резервирования/восстановления. Редактируемые исходники скопировать обратно в content/citadel_addons/bebop_arena SDK. Штатные ассеты SDK и сам SDK не включены. Сохраняйте установленный SDK отдельно, если планируется редактирование карты.
