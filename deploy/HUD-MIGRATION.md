# Персональный HUD — переход со старой раздачи

Старый `guest-hud/share.cjs` пересылал всем экран одного локального игрока.
Новый `deploy/server.cjs` получает `modlock --json` HostEvent и хранит UI отдельно
по Steam ID. TCP 4321 остаётся прежним; дополнительный порт открывать не нужно.
Кнопки по-прежнему исполняются игровым сервером от лица отправителя.

## Один раз на VPS

1. В окне старого `share.cjs` нажать Ctrl+C и закрыть окно.
2. В окне обновлятора `deploy/server.cjs` нажать Ctrl+C. Это остановит игровой сервер.
3. Открыть терминал в каталоге клона bebophookcup, где находятся `deploy` и `main.ts`:

   ```powershell
   git pull --ff-only origin dev
   .\deploy\Start-Arena.cmd
   ```

4. Новый обновлятор сам занимает TCP 4321 и запускает Modlock. Старый share.cjs
   больше не запускать. Если порт занят, новый запуск остановится с понятной ошибкой.
5. Всем игрокам раздать новый клиентский ZIP. Старый клиент с новым серверным HUD
   несовместим: у него нет выбора интерфейса по Steam ID.

## Игрокам

Закрыть Deadlock и старое окно HUD. Распаковать новый ZIP в отдельную папку,
войти в нужный аккаунт Steam, запустить Start HUD.cmd. Окно оставить открытым.
При смене Steam-аккаунта перезапустить батник.

## Проверка в игре

Два игрока и наблюдатель: один выбирает P1 — только у него Ready/Spectate;
второй видит занятое P1 и свободное P2. После выбора P2 у наблюдателя выбор
исчезает. Проверить выход/повторный вход, завершение матча и перезапуск сервера.
Counterspell выдаётся участникам автоматически; использовать обычную кнопку
парирования во время раунда. КД предмета 30 секунд, между раундами не сбрасывается.

Проверены локальные тесты, бинарный протокол и настоящие события CLI в sandbox.
Полный multiplayer-тест нового клиента в Deadlock ещё требуется.
