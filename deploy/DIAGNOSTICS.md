# Диагностика

По одному `0xc0000005` нельзя установить причину нарушения доступа к памяти.

1. Запускать обновлённый deploy/server.cjs. Журналы пишутся в `C:\BebopServer\logs`: UTC-время, commit, PID, события Modlock без UI-пакетов, stderr и завершение процесса. Старый updater нужно перезапустить.
2. Скачать [ProcDump с Microsoft](https://learn.microsoft.com/en-us/sysinternals/downloads/procdump), распаковать и запустить отдельный PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy\Watch-Crashes.ps1 -ProcDump C:\Tools\procdump64.exe
```

Наблюдаемый процесс — **modlock-host.exe**. Принять лицензию; при отказе в доступе запустить от администратора. Сохраняются полные дампы необработанных исключений, максимум пять. Они могут занимать гигабайты. Собственный обработчик крашей игры может помешать перехвату: дамп не гарантирован.

3. После сбоя выполнить:

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy\Collect-Diagnostics.ps1
```

4. Сохранить папку `C:\BebopDiagnostics-ДАТА`, точное время, число игроков и последнее действие перед сбоем. Передавать приватно; дампы и журналы не коммитить, в них возможны приватные данные.

Журнал ограничен восемью сегментами по 16 MiB на запуск updater. Старые запуски не удаляются автоматически — периодически архивировать. Если сбор не был включён, скрипт может найти события Windows, но не восстановит отсутствующие дампы и логи.
